## 业界公认做法（综合多个来源）

### 1. 硬件方案（精度从高到低）

- **Monsoon 功率计 / 电源分析仪**：直接给主板供电并测电流，
  精度 µA 级，是媒体（包括极客湾）的标配。**需要拆机或改装电池座**，
  我们做不到。
- **USB 功率计（Power-Z 等）**：测充电功率反推放电，
  但充电时无法测真实放电，且效率转换引入误差。
- **PMIC 库仑计（我们的方案）**：设备自带 charge_counter，
  分辨率 1000 单位（0.001Ah），分钟级窗口可用。
  **这是不拆机条件下的最优解。**

### 2. 负载方案

- 极客湾用**自研负载**（据知乎争议，大核占比 >99%），
  而非 Geekbench 等公开跑分——为了精确控制每个核的负载。
- 我们的 `bench`（自研整数运算循环）思路一致：
  单核钉核、固定时长、输出 ops 计数。

### 3. 数据处理（可借鉴的核心）

- **多轮测量取中位数**：极客湾"上万组数据"本质是大量重复后的统计。
- **能效曲线 = 功耗-性能曲线**：横轴是性能（分数/吞吐），
  纵轴是能效（性能/功耗 或 功耗/性能）。
  **不是简单的功耗-频率曲线**——不同频率下吞吐不同，
  必须同时呈现。
- **相对关系 > 绝对值**：民间测试无法完全消除基线误差，
  曲线的形状、拐点、不同 SoC 之间的相对关系比绝对数值更可靠。

## 我们的差距与对策

| 差距 | 极客湾做法 | 我们的对策 |
|------|-----------|-----------|
| 功耗计精度 | Monsoon µA 级 | 库仑计 + 足够长窗口（空闲 ≥300s） |
| 负载控制 | 自研，大核占比 >99% | 已有 bench（单核钉核整数循环） |
| 重复轮次 | 上万组 | 至少 3 轮取中位数，给极差带 |
| 曲线口径 | 功耗-性能曲线 | **补吞吐-能效双轴图**，不只画 P-f |
| 环境控制 | 恒温箱、拆机 | 清后台 + QC 准入 + 温度监控 |
| 基线扣减 | 未公开 | 每测点独立空闲窗口（已实现） |

## 下一步改进（代码层面）

1. **吞吐-能效双轴图**：横轴吞吐（Mop/s），纵轴能效（nJ/op），
   每个频点一个点，能直接看出"多花多少电买多少性能"。
2. **误差带**：同频点多轮测量画极差带（min~max），不只画中位线。
3. **温度监控**：每个测点记录 CPU 温度，过热降频的点标记剔除。
4. **数据有效性标记**：idle_zero、QC_FAIL、过热降频的点在图上加注释。
