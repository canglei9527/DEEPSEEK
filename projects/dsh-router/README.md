# dsh-router

A ZCode port of [`yjh051108/dsh-routing-suite`](https://github.com/yjh051108/dsh-routing-suite)
(MIT) — the task-aware reasoning-mode router, adapted to ZCode's extension
surface.

Upstream is built for **DSH** (DeepSeek Harness) and installs through
`dsh plugin --profile web add`, a cordis bundle patch, and an agent-preset
directory. ZCode has none of those layers, so this port keeps what is
carryable and is explicit about what is not.

## What it does

Every user prompt is classified into a **band**, and a matching working-style
directive plus the current workflow stage is injected **near-field** — in the
same request as the user's message, costing no extra API round-trip.

| band | working style | chosen when |
|---|---|---|
| `react` | hands-on production: build, verify, fix; no unrequested ceremony | build-heavy prompt (`写一个`/`创建`/`build`/`create`/`实现`…) |
| `spec` | inspect-and-plan: ground in real code, minimal compatible change | fix-heavy prompt (`修复`/`调试`/`重构`/`fix`/`debug`…) |
| `weak` | route yourself per task | keywords tie or none match — the ambiguous fallback |
| `mixed` | transition band | never automatic; explicit opt-in only |

The band **locks** at the first classification, because upstream measured that
behavior phase-transitions on the first request rather than remaining tunable.
The one exception: `weak` means "never cleanly classified", so clear one-sided
evidence on a later prompt upgrades it once.

Stages advance 0 → 3 (understanding → planning → development → verification)
on tool evidence. A mutation made while plan mode is active does not count as
development progress.

## Install

```sh
node scripts/install.mjs
```

That copies this checkout into the local ZCode client — the marketplace
directory and the plugin cache — and registers the marketplace, the plugin,
and its enabled state in the client's state files. It is idempotent: re-running
refreshes the installed copy and leaves every unrelated plugin untouched.

**Open a new session afterwards.** ZCode snapshots plugin hooks when a session
starts, so an already-running session keeps the old hook list.

Where things land:

| | Path |
|---|---|
| Source of truth | this checkout |
| Marketplace | `~/.zcode/cli/plugins/marketplaces/local-dsh-router/` |
| Plugin cache | `~/.zcode/cli/plugins/cache/local-dsh-router/dsh-router/<version>/` |
| Runtime state | `~/.zcode/cli/plugins/data/dsh-router@local-dsh-router/` |

`marketplace.json` is generated by the install script, not committed — it
carries an absolute path to this checkout and would be wrong on any other
machine.

## Components

| Component | Path | Purpose |
|---|---|---|
| Hooks | `hooks/` | `SessionStart` (bootstrap once), `UserPromptSubmit` (route + inject), `PostToolUse` (stage state) |
| Router core | `hooks/lib/router-core.mjs` | Ported pure logic: classification, bands, personas, stage advance |
| Guidance | `hooks/lib/guidance.mjs` | The injected text: directives, stage guides, proactivity |
| State | `hooks/lib/state.mjs` | Per-session state and config, under `~/.zcode/cli/plugins/data/dsh-router@local-dsh-router/` |
| Skill | `skills/router-mode/` | Inspect or change the routing mode |
| Command | `/router-status` | Report the current routing state |
| Agents | `agents/router-*.md` | `spec`/`react` subagents with the persona in their own system prompt |
| Tests | `tests/` | 34 tests; 7 are differential comparisons against upstream |

## Configuration

`~/.zcode/cli/plugins/data/dsh-router@local-dsh-router/config.json` (all optional):

```json
{ "mode": "auto", "verbosity": "full", "enabled": true }
```

- `mode` — `auto`, or force a band: `spec`/`react`/`mixed`/`weak`, or a number
  (`0` spec, `30` mixed, `100` react).
- `verbosity` — `full`, `compact` (decision + directive only), `off`.
- `enabled` — `false` disables every hook.

Changes apply from the next message; no restart needed.

## Tests

```sh
node --test tests/router-core.test.mjs tests/hooks.integration.test.mjs
```

`tests/router-core.test.mjs` compares the ported functions against the actual
upstream `router-core.mjs` when a checkout is reachable, and reports the skip
explicitly when it is not. Point `DSH_ROUTING_SUITE` at a
`dsh-routing-suite/preset/router-standard/router-core.mjs` to enable them
anywhere.

## Fidelity: what is faithful, what is approximated, what is missing

**Faithful (differential-tested against upstream):** `classifyTask`,
`bandOf`, `bandFor`, `personaFor`, `isComplexTask`, `isFlashModel`,
`clamp01`, `parseMode`, `advanceStage` (modulo tool-name mapping), and the
persona strings themselves.

**Approximated.** Upstream swaps the **system prompt** persona — that swap is
what its measurements condition on. ZCode exposes no system-prompt hook, so
the persona is restated as a **near-field working-style directive**. This is a
tail-position approximation of a system-prompt change, not an equivalent, and
the upstream performance figures (92-94% cache hits, 96% routing, 100%
convergence) were measured on DSH and **do not transfer**.

**Missing.** Upstream also gates the **tool catalog per stage** — tools stay
invisible until their stage opens. ZCode exposes no hook that can add or
remove tools, so this port reports the stage and never restricts tools. The
`agents/` subagents are the one place a real system prompt is available, which
is why `spec`/`react` are offered there.

**Dropped.** Upstream's `engram_*` memory tools, `tools_catalog`/`tools_help`
progressive disclosure, `phase_advance`, `delivery_check`, `dev_page_check`,
and the `dev_*` injector/admin tools have no ZCode counterpart and are not
ported. Live preset reloading is unnecessary here: hooks are read per event.
